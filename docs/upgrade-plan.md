## 一、点击完成功能

### 1.1 核心交互流程

**触摸捕获 → 坐标匹配 → API更新 → 刷新显示**

```
用户触摸屏幕
    ↓
plan_a_main.py 捕获 x,y（原始物理坐标）
    ↓
坐标映射：x_render = 600 - y_phys, y_render = x_phys
    ↓
判断触摸区域：
  - 右侧导航区（x_render >= 740）→ 切换视图
  - 内容区 → 进入完成判定逻辑
    ↓
在内容区中匹配待办项的 □ 位置
    ↓
调用 API: PATCH /api/events/{id} { "completed": true }
    ↓
重新拉取 /api/events/tree → 重新渲染
```

### 1.2 父子联动规则

| 场景 | 行为 |
|------|------|
| 点击子级的□ | 标记子级 completed=true，检查同父级下是否所有子级都完成，如果是则父级也自动 completed=true |
| 点击父级的□ | 视为无效，无任何响应 |
| 子项全部完成后父级自动完成 | 后续新建子项，父级保持 completed=true（不自动重新激活） |

### 1.3 坐标匹配算法

每个视图的待办项 □ 位置不同，需要逐视图计算：

**待办列表视图（render_todo_view）**：
```
□ 位置：x = content_x + 20 + indent, y = item_y（每项 28px）
匹配容差：±8px
```

**三日视图（render_three_day_view 待办区）**：
```
□ 位置：x = content_x + 3 + indent, y = item_y（每项 22px）
```

**单日/今日视图（render_day_or_home_view）**：
```
□ 位置：x = content_x + 30 + indent, y = item_y（每项 25px）
```

### 1.4 完成后的展示样式

- completed=true 的待办：文字颜色变灰（fill=150），移动到列表底部
- 排序时 completed 的排在最后，同一优先级内按原有顺序排列

当前待办列表已按四象限优先级排序：

| 优先级 | 象限 | importance | urgency |
|--------|------|-----------|---------|
| 1 | 重要紧急 | important | urgent |
